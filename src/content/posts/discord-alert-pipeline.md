## 문제 인식

자료 분석 실패나 API 타임아웃이 가끔씩 발생했는데, 발생 빈도가 낮다 보니 방대한 로그 속에 묻혀 아무도 알아채지 못했습니다. 결국 사용자가 먼저 문의를 남긴 뒤에야 문제를 인지하는 일이 반복됐습니다.

## 원인 분석

로그 자체는 다 남고 있었지만, "누군가 실시간으로 로그를 들여다보고 있어야만" 문제를 발견할 수 있는 구조였습니다. 저빈도 에러일수록 이런 수동 감시 방식에서 가장 먼저 빠져나가는 신호가 됩니다.

## 의사결정

로그를 사람이 찾아가는 대신, 에러가 나면 사람에게 알아서 찾아오도록 파이프라인을 뒤집기로 했습니다.

- 에러 로그를 Pub/Sub으로 발행하고, Cloud Function이 이를 구독해 Discord로 실시간 전파합니다.
- 매번 원문 로그를 그대로 보내면 노이즈가 커지므로, 에러 메시지 패턴을 11종으로 자동 분류해 어떤 유형의 문제인지 바로 구분할 수 있게 했습니다.
- 실시간 알림과 별개로, 3시간 주기로 누적 현황을 요약한 상태 리포트도 함께 보내 추세를 놓치지 않도록 했습니다.

## 해결

에러 발생 즉시 Discord 채널에 분류된 알림이 오고, 3시간마다 요약 리포트가 쌓입니다. 실시간성과 추세 파악을 동시에 확보한 구조입니다.

## 최종 성과

저빈도 에러까지 추적 가능한 운영 체계를 확보했습니다. 사용자 제보보다 먼저 문제를 인지하는 경우가 늘었고, 에러 유형별 분류 덕분에 원인 파악 시간도 줄었습니다.
