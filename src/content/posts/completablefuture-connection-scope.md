## 문제 인식

외부 AI API 여러 개를 순차로 호출하는 API가 있었는데, 150 VUs 부하 테스트에서 전량 실패했습니다.

## 원인 분석

외부 API를 하나씩 순서대로 호출하다 보니, 각 호출의 응답을 기다리는 동안에도 트랜잭션이 열려 있어 DB 커넥션을 계속 붙잡고 있었습니다. 호출이 8개라면 그 대기 시간이 그대로 누적돼 커넥션 하나당 점유 시간이 7초를 넘겼고, 동시 요청이 조금만 몰려도 커넥션 풀이 금방 고갈됐습니다.

## 의사결정

두 가지를 분리하기로 했습니다.

- **호출 자체**: 순차 대기 대신 CompletableFuture로 외부 API 호출을 병렬로 실행합니다.
- **커넥션 점유 시간**: 외부 API 응답을 기다리는 구간과 DB 작업 구간을 분리해, 대기 중에는 커넥션을 붙잡지 않도록 합니다.

## 해결

CompletableFuture 기반으로 호출을 병렬 실행하도록 리팩토링하고, DB 커넥션 점유 시간을 실제 DB 작업 구간으로만 좁혔습니다.

## 최종 성과

p95 응답 속도가 7.2초에서 363ms로 줄었습니다. 병렬화로 대기 시간 자체를 줄이고, 커넥션 점유 시간 분리로 풀 고갈 위험까지 함께 해결했습니다.
