LLM은 마크다운을 "대체로 맞게" 씁니다. 문제는 렌더러가 그 "대체로"를 봐주지 않는다는 점입니다.

모릭은 강의 자료를 분석한 결과를 마크다운으로 생성해 react-markdown으로 렌더링하는데, 렌더링 버그 제보가 세 가지 다른 얼굴로 반복해서 들어왔습니다.

## 증상 도감

**증상 1 — 표 다음에 오는 리스트가 통째로 깨진다.** 모델이 표를 그린 뒤 요약 불릿을 이어 붙이면, 화면에는 `**핵심 요약**: ...` 같은 마크업 기호가 서식 적용 없이 텍스트 그대로 노출됐습니다.

**증상 2 — 중첩 리스트의 들여쓰기 단계가 뒤섞인다.** 2단계였던 항목이 화면에서는 4단계처럼 보이거나, 서로 다른 두 단계가 같은 깊이로 겹쳐 보였습니다.

**증상 3 — 표 아래 산문이 코드블록으로 감싸인다.** 모델이 산문 문단을 언어 태그 없는 코드펜스로 잘못 감싸서, 볼드나 링크가 전혀 렌더링되지 않고 통째로 회색 코드 박스 안에 갇혔습니다.

처음에는 프롬프트에 "마크다운 규칙을 지켜라"는 지시를 더 강하게 넣는 방식으로 대응했습니다. 모델이 규칙을 어기는 빈도는 줄었지만 0이 되지는 않았습니다.

## 세 증상을 관통하는 하나의 원인

세 증상은 겉보기엔 서로 다른 버그였지만, 파고들면 CommonMark 사양과 LLM 출력 습관이 어긋나는 같은 지점에서 나오고 있었습니다.

증상 1의 원인은 CommonMark 사양 자체였습니다. CommonMark에서 표는 리스트의 연속성을 끊습니다.

표 다음에 들여쓰기된 `- 항목`이 오면, 파서는 이걸 "표에 이어지는 리스트"가 아니라 "들여쓰기된 코드블록"으로 해석합니다.

```python
def _deindent_bullets_after_table(lines: list[str]) -> list[str]:
    """표 바로 뒤에 오는 들여쓴 하위 불릿(`    - ...`)은 CommonMark에서 표가
    부모 리스트의 연속을 끊어버려 리스트가 아닌 '들여쓰기 코드블록'으로
    오인식된다(**볼드**·$수식$·- 불릿이 그대로 텍스트로 노출됨)."""
```

증상 2의 원인은 스케일 불일치였습니다. 프롬프트는 모델에게 중첩 리스트를 4칸 들여쓰기로 쓰도록 지시하고 있었는데, CommonMark 정규화 로직은 "2칸 = 1단계"를 기준으로 재해석합니다.

원본 4칸을 그대로 넘기면 2단계로 오인식되어 들여쓰기가 8칸으로 두 배가 되거나, 서로 다른 두 단계가 같은 폭으로 겹쳐 계층 정보 자체가 사라지는 회귀가 실제로 발생했습니다.

증상 3의 원인은 모델이 표 아래에서 산문(불릿+볼드+한글)을 언어 태그 없는 코드펜스로 잘못 감싸는 습관이었습니다. 위키 링크(`[[...]]`)나 인라인 노트 토큰이 표 셀 경계와 겹쳐 팝오버 위치가 애매해지는 것도 같은 계열의 문제였습니다.

원인이 하나가 아니라, "LLM 출력의 느슨함"과 "CommonMark 파서의 엄격함" 사이 간극에서 계속 새로운 형태로 터져 나오고 있었습니다.

## 서비스 코드 안에서 계속 땜질할 수 없었던 이유

처음에는 이 문제들을 백엔드 코드베이스 안에서 정규식으로 하나씩 땜질했습니다. 표 직후 들여쓰기를 되돌리는 정규식, 4칸을 2칸으로 재해석하는 정규식, 코드펜스 오검출을 막는 정규식이 파일 하나에 계속 쌓였습니다.

새 증상이 발견될 때마다 빠르게 패치를 낼 수 있다는 장점은 있었지만, 회귀가 하나 고쳐질 때마다 다른 정규식과 충돌할 위험이 커졌습니다. 무엇보다 이 문제는 모릭만의 문제가 아니라 LLM으로 마크다운을 생성하는 모든 서비스가 겪을 수 있는 문제였습니다.

그래서 범용 정규화 로직을 별도 라이브러리(`llm-markdown-sanitizer`)로 분리하기로 했습니다. 경계는 다음과 같이 나눴습니다.

- **라이브러리가 책임지는 범용 정규화**: emphasis 경계 처리, 표 확장/복구, 리스트 들여쓰기의 CommonMark 스케일 정규화, 코드펜스 감싸기/닫힘 처리, 코드 내용 보호
- **서비스에 남긴 도메인 전용 로직**: 위키 링크 표기, 페이지 참조(`p.N`) 위치 정리처럼 모릭에만 있는 규칙

```python
def clean_markdown_response(text) -> str:
    """범용 마크다운 정규화(emphasis 경계, 표 확장/복구, 리스트 정규화, 코드펜스
    감싸기/닫힘 처리, 코드 내용 보호)는 `llm-markdown-sanitizer` 라이브러리에
    위임합니다. 여기서는 라이브러리 스코프 밖인 서비스 도메인 전용 처리만
    담당합니다."""
    ...
    pre_lines = _normalize_list_indent_levels(pre_lines)  # 4칸 습관을 CommonMark 2칸/단계로 재작성
    cleaned = _sanitize_markdown("\n".join(pre_lines))     # 이후는 라이브러리에 위임
```

들여쓰기 스케일 문제는 라이브러리를 고치는 대신, 라이브러리에 넘기기 전 단계에서 "원본의 상대적 중첩 관계"만 읽어 절대 폭이 아닌 depth 기준으로 2칸/레벨로 재작성하는 전처리를 추가했습니다. 모델의 4칸 습관(프롬프트)은 건드리지 않고, 라이브러리가 기대하는 스케일에 맞춰주는 얇은 어댑터를 하나 끼운 셈입니다.

코드펜스 오검출 문제도 같은 경계 원칙으로 처리했습니다. 언어 태그가 없는 펜스 안에 불릿과 볼드, 한글이 섞여 있으면 실제 코드가 아닌 산문으로 판단해 펜스를 벗겨내되, 언어 태그가 명시된 펜스는 내용이 산문처럼 보여도 그대로 보존합니다.

```python
check(
    "labeled fence is preserved even if content looks like prose",
    "```python\n- **not real code but has a language tag**\n```\n",
    expect_substring="```python",
)
check(
    "real code with no bullets after a table stays fenced",
    "| a | b |\n|---|---|\n| 1 | 2 |\n\n```\nMOV AX, 1\n```\n",
    expect_substring="```\nMOV AX, 1\n```",
)
```

## 일반화 이후에도 남은 회귀

라이브러리로 분리한 뒤에도 회귀는 남았습니다. 4단계로 중첩된 리스트(A-B-C-D 레벨)가 라이브러리를 거치며 서로 다른 두 단계가 같은 들여쓰기 폭으로 붕괴되는 경우, 페이지 참조 문구(`그림 -p.1`)를 하위 불릿으로 확장하는 과정에서 라이브러리의 2칸 스케일과 어긋나 8칸으로 배가되는 경우가 실제로 발생했습니다.

이런 케이스들은 단위 테스트로 고정해, 이후 라이브러리 버전이 올라가거나 도메인 전처리 로직이 바뀌어도 같은 회귀가 조용히 재발하지 않도록 막아뒀습니다.

```python
# 4-space/레벨 중첩이 라이브러리의 2-space=1단계 스케일과 어긋나
# 단계가 배가/붕괴되면 안 되는 회귀를 고정한 테스트
four_level = "- A레벨\n    - B레벨\n        - C레벨\n            - D레벨\n"
result = clean_markdown_response(four_level)
indents = [len(l) - len(l.lstrip(" ")) for l in result.splitlines() if l.strip()]
assert len(set(indents)) == 4
```

표 셀 경계 근처의 인라인 노트 토큰(`[[help:...]]`, `[[exam:...]]`)도 같은 방식으로 고정했습니다. 표 안, 표 직전/직후 문장에 붙은 토큰은 팝오버 위치가 애매해지므로 제거하되, 표에서 충분히 떨어진 문장의 토큰은 그대로 유지되어야 합니다.

```python
check(
    "inline token far from any table is preserved",
    "- 문장. [[help:유지되어야 함]]\n\n- 다른 문장\n\n| a | b |\n| :--- | :--- |\n| 1 | 2 |\n",
    expect_substring="[[help:유지되어야 함]]",
)
```

   증상 하나하나에 정규식으로 대응했다면 회귀는 줄지 않고 계속 쌓였을 겁니다.
