## 문제 인식

분석 요청 버튼을 짧은 시간에 여러 번 누르면 크레딧이 마이너스로 내려가는 문제가 있었습니다.

## 원인 분석

크레딧 차감이 AI 워커 쪽에서 비동기로 처리되고 있었습니다. 즉 사용자가 버튼을 누른 시점과 실제로 크레딧이 차감되는 시점 사이에 지연이 있었고, 그 짧은 틈에 연달아 요청을 보내면 아직 차감이 반영되지 않은 잔액을 기준으로 여러 요청이 통과됐습니다.

## 의사결정

두 가지를 조합했습니다.

- **선차감**: 프론트에서 클릭 즉시 잔액을 먼저 차감해 화면에 반영합니다. 실제 처리 여부와 무관하게 다음 클릭 시점에는 이미 줄어든 잔액 기준으로 판단하므로, 연타로 지연 구간을 노리는 게 불가능해집니다.
- **실패 시 환불**: 실제 AI 처리가 실패하면 워커가 환불 API를 호출해 차감분을 되돌립니다.

낙관적으로 먼저 차감하고, 문제가 생기면 나중에 보정하는 방식을 택한 이유는 매 요청마다 서버 왕복으로 잔액을 확인하는 것보다 사용자 체감 응답이 빠르고, 실패 케이스는 비교적 드물어 보정 비용이 크지 않기 때문입니다.

## 해결

프론트의 선차감 로직과 AI 워커의 실패 시 환불 API 호출을 연결해, 잔액이 마이너스로 내려가지 않으면서도 응답성은 그대로 유지했습니다.

## 최종 성과

연타로 인한 마이너스 크레딧 문제가 재발하지 않는 것을 확인했습니다. 별도의 서버 사이드 락 없이 클라이언트 상태 갱신 순서만 조정해 해결한 케이스입니다.
