## 문제 인식

모릭은 사용자가 올린 강의자료를 AI로 분석해 요약·퀴즈 등을 만들어주는 서비스입니다. 수백 페이지짜리 문서를 분석하는 요청은 몇 분씩 걸리는데, 이 연산을 API 요청을 받은 스레드가 그대로 붙잡고 처리하고 있었습니다. Cloud Run의 요청 타임아웃(60초)을 넘기면 504가 발생했고, 그 요청은 응답도 못 받은 채 서버 스레드만 계속 점유했습니다.

## 원인 분석

문제의 본질은 "즉시 응답 가능한 API"와 "오래 걸리는 연산"을 같은 요청-응답 사이클 안에 억지로 우겨넣은 것이었습니다. Cloud Run 같은 서버리스 환경은 요청당 처리 시간에 제약이 있어서, 연산이 그 제약을 넘는 순간부터는 구조적으로 실패할 수밖에 없습니다.

## 의사결정

요청을 받는 경로와 실제 연산을 처리하는 경로를 분리하기로 했습니다.

- API는 분석 작업을 Redis 큐에 등록만 하고 즉시 응답합니다.
- 실제 분석은 별도의 ARQ(Async Redis Queue) 워커 프로세스가 큐에서 작업을 꺼내 백그라운드로 수행합니다.
- 클라이언트는 작업 ID로 진행 상태를 폴링하거나, 완료 시 별도 알림을 받습니다.

## 해결

FastAPI 기반 API 서버와 ARQ 워커를 별도 프로세스로 배포했습니다. API 서버는 요청을 큐에 넣는 역할만 하므로 항상 빠르게 응답하고, 워커는 처리 시간에 제약 없이 문서 분석을 끝까지 수행합니다.

## 최종 성과

요청 처리 성공률 97.4%를 달성했습니다. 문서 길이와 무관하게 API 응답 자체는 즉시 오고, 실패하더라도 요청 스레드가 아니라 워커 단위에서 격리되어 다른 요청에 영향을 주지 않습니다.
